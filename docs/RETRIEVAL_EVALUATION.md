# Local embedding retrieval

Implemented and measured on 21 October 2026 (India time). `POST /api/evidence` accepts `{ "query": "INS 955", "limit": 4 }` with a same-origin localhost request. It returns genuine model cosine scores, lexical BM25 scores, exact identity matches, original source metadata and dated limitations. Returned passages are evidence candidates, never a clinical verdict or proof of current law.

Run `npm run embeddings:prepare` once with internet access, then `npm run embeddings:evaluate`. Preparation downloads approximately 24 MB of Apache-2.0 model/tokenizer assets to ignored `.data/models/`, verifies finite 384-dimensional output, and writes the compact reproducible vector index under `data/`. Runtime queries disable all remote model loading and execute on local Node CPU. No health text or query is sent to Hugging Face. No API key is needed. The server retains a single pipeline and rejects concurrent work while busy; command-line scripts dispose it explicitly.

The pretrained encoder is [Xenova/all-MiniLM-L6-v2](https://huggingface.co/Xenova/all-MiniLM-L6-v2), the Transformers.js ONNX conversion of [sentence-transformers/all-MiniLM-L6-v2](https://huggingface.co/sentence-transformers/all-MiniLM-L6-v2), pinned at revision `751bff37182d3f1213fa05d7196b954e230abad9`. Transformers.js 4.3.1 was measured. Mean pooling and unit normalization follow the model usage. `data/semantic-model-manifest.json` records actual downloaded byte sizes and SHA-256 values. The q8 model itself is 22,972,370 bytes. Runtime does not fabricate vectors or use hand-built concept vectors.

The corpus contains 16 curated entries in `src/lib/knowledge.ts`: WHO sodium, non-sugar-sweetener, carbohydrate-quality and free-sugars guidance; NIDDK diabetes meal education; eight FAO/JECFA/Codex additive identity records; bibliographic metadata for ICMR-NIN's 2024 Indian Dietary Guidelines; and two FSSAI labelling sources. Every record has a license/terms note: known restrictions are recorded, while unverified terms are explicitly labeled unknown; this is provenance tracking, not legal clearance. The FSSAI records explain dated allergen wording, not a particular product's allergen presence or current compliance. The additive records support identity and synonym lookups only; their source pages do not establish product presence, dose or national authorization. NutriScan does not reproduce the ICMR-NIN recommendations because its notice restricts electronic product use without prior written permission. It stores original short summaries and citation metadata rather than whole source publications; the WHO sugars publication is all-rights-reserved and is linked without reproducing its wording. Corpus version `2026-10-21.8` and a SHA-256 of source IDs, text and URLs must match the index; source drift fails closed and requires regeneration. License metadata is not part of the embedding fingerprint, so this metadata-only update did not require a re-embed. Static retrieval never establishes a current Indian legal permission, product dose or personal carbohydrate target.

## Measured developer evaluation

The 18 developer-authored queries in `data/semantic-evaluation-queries.json` were written before this measurement; exact terms, additive identifiers, paraphrases, three free-sugars questions and package-versus-population-guidance questions are mixed. Every query has a declared relevant source ID. `data/semantic-evaluation-results.json` contains individual ranks, actual cosine/BM25 scores, timestamps and latency. Lexical and pure semantic scores rank all ten corpus entries; hybrid exposes five results. Recall@3 means whether the declared relevant source occurs in the first three results.

| Method | Top-1 correct | Recall@3 | MRR@5 |
|---|---:|---:|---:|
| Lexical BM25 | 17/18 (94.4%) | 17/18 (94.4%) | 0.9556 |
| MiniLM cosine only | 16/18 (88.9%) | 18/18 | 0.9444 |
| Hybrid + exact identity | 18/18 (100%) | 18/18 | 1.0000 |

The corpus grew from 14 to 16 entries and the same 18 developer-authored queries were rerun without changing their labels. Lexical Recall@3 fell from 18/18 to 17/18 because the sodium paraphrase moved from rank 3 to rank 5; MiniLM Top-1 fell from 17/18 to 16/18 because the exact sucralose query moved from rank 1 to rank 2. Hybrid remained 18/18 Top-1 and Recall@3. The hybrid uses 90% cosine and 10% normalized BM25, with a separate exact-identity boost. These are **development/tuning results**, not an independent held-out improvement claim, clinical accuracy, OCR accuracy, or general web-search accuracy. The corpus remains small and the query labels were written by the implementation team; no independent evaluator has judged relevance. Broader corpora and independently authored held-out queries remain necessary.

In the refreshed Next.js API receipt, the first query after process startup took 2.082 seconds and two warm queries took 12 and 18 ms on this machine. These are local desktop measurements, not a mobile performance guarantee. Remote Gemini, current-law research and genuine-photo OCR acceptance are separate integration gates.

Real localhost Next.js HTTP checks are recorded in `data/semantic-api-receipt.json`: the FSSAI allergen-wording query returned HTTP 200 with the 2023 FAQ first at corpus version `2026-10-21.8`; exact `INS 955` and blood-pressure paraphrase queries still returned `fao-955` and `who-sodium` first. The allergen request took 2,082 ms cold; the two warm requests took 12 and 18 ms on this machine. A hostile Origin returned 403 and an invalid bound returned 400. The local model assets matched their recorded hashes before index regeneration; no model download or remote provider call occurred. The mobile/desktop acceptance in `docs/evidence/local-evidence-browser.json` additionally checked the `INS 211` JECFA identity card, its publisher/jurisdiction and limitations, and a typed potassium-sorbate follow-up that explicitly did not claim package presence. Six same-origin evidence requests per viewport returned HTTP 200; accessibility and page-error checks were clear. The check caught and led to repair of Next's localhost-versus-127.0.0.1 Request URL normalization in the shared API gate. These are actual local HTTP/browser receipts, not external provider acceptance.

Known limitations: a tiny English corpus, no calibrated out-of-domain rejection, model token truncation, unknown source supersession, no independent annotation, and no freshness guarantee. Unrelated queries can still retrieve weakly similar passages. The response explicitly reports this limitation; it must not turn a top-ranked passage into a supported answer without checking applicability.

## Conservative candidate floor and intent guard

A separate 13-query diagnostic is recorded after the original ranking evaluation. It includes five unrelated requests, six supported or scope-boundary questions and two current-law queries. Before adding a guard, the unrelated requests scored 0.10–0.16 on the hybrid scale, while the four original supported examples scored 0.34–0.65. A current ORS-law query scored 0.40 against the ICMR bibliography, showing that similarity alone could surface an irrelevant dietary record for a legal question.

The endpoint now suppresses candidates below a 0.30 development score floor and routes queries containing common regulatory terms (including ORS, FSSAI and Gazette) to a no-match response before model inference. In the latest 13-case run, all five general out-of-domain and both current-law queries returned no local candidates; all six supported/scope-boundary probes returned an expected source, including the FSSAI FAQ for a wording question that did not ask for current compliance. Chrome acceptance checked the additive record, WHO fibre and free-sugars guidance, unrelated-query abstention, and current-law abstention at mobile and desktop sizes. Receipt: `docs/evidence/semantic-boundary-diagnostic.json`; browser evidence: `docs/evidence/local-evidence-browser.json`.

This is a conservative guard tested on developer-authored probes, not a calibrated relevance probability or an independent query benchmark. Novel legal wording and unrelated questions that score above the floor may still retrieve weak matches. Current-law verification remains in the separate dated regulatory workflow.

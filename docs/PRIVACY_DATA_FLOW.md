# Privacy and data flow

Photos: selected file → local browser Blob → optional native barcode detection where supported → bounded canvas/prepared image → local Tesseract worker/WASM → observations in memory. Worker and English language data and fonts are served from this local installation. Barcode decode and OCR run in the browser; originals are not posted to an API by ordinary scanning. Removed/replaced/new-scan blobs are released. Browser memory is not a secure vault.

Health context: dietary preferences, food allergies, food intolerances, user-declared health considerations, goals and optional reference details remain in React memory unless the user separately opts in to remembering them on this device. The profile starts empty and does not ask for meal measurements. The opt-in copy is stored in a dedicated IndexedDB key, separately from scans and conversations, and is excluded from JSON exports. Anyone with access to this browser profile can read it; it is not encrypted or synced. Unchecking the option removes the remembered copy and leaves the current session values; Clear context removes both. Allergy and intolerance inputs remain separate; neither is a diagnosis. Derived calculation assumptions/results may appear in reports. Review reports before sharing. Product lookup may include the selected country as a catalog filter; it does not send other profile fields. A user must separately consent before any profile text is sent to Gemini; if every field is blank, Gemini receives no profile object. Other public searches send the text entered in the research panel. No account, cloud sync or encryption claim.

Saved scans: opt-in IndexedDB on this browser profile, up to20 extracted label records. They include raw OCR text, potentially identifiers printed on packaging and user corrections. They exclude original photos and free-text health context. A separate explicit option stores up to 30 recent local question-and-answer turns with the scan; these turns may contain personal details, but profile fields, original photos and Gemini answers are excluded. Turning that option off removes saved turns; clearing history removes saved scans and conversations. Exported files are not removed by clearing browser history. Shared browser-profile access can expose saved scans and turns.

Public search: explicit user action sends the visible product/science/recall search terms through this loopback server to fixed public source APIs. Product-candidate lookups may also send the selected country as a catalog-tag filter. The UI warns not to place personal medical details in public terms. Local semantic queries stay on the server machine and use a predownloaded model; they never transmit query text to Hugging Face.

Gemini: default disabled. Requires server-only key, model, explicit enable flag and request consent. Synthesis sends extracted label, question, optional profile, source summaries and image-handle metadata. Browser retains image bytes until a disclosed image-send action. Original/cropped image request is validated against session handles. Image route validates signatures, decodes bounded dimensions and strips metadata before Google transmission. Provider retention/billing policies apply; local-first does not imply private cloud inference.

No raw medical context, photos, keys or conversations are intentionally logged by application code. Development framework logs request paths/compilation status. Request IDs and response metadata are non-content receipts. Public source responses are untrusted and rendered as text, never HTML instructions.

API surface: same-origin local-only POST, fixed remote hosts/no redirects, body/response limits, timeouts and in-process request/concurrency limits. These are local development protections, not authenticated multi-tenant production controls. No Firebase, production writes, public tunnel or deployment.

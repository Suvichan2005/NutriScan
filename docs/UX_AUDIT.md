# UX and browser evidence

Updated: 2026-10-21. The Codex in-app browser is disabled in Work settings, so this review used the locally installed Google Chrome through Playwright 1.64 against the running local NutriScan app. Screenshots came from the actual browser at 390 × 844 and 1440 × 1000 CSS pixels. The Next.js development badge was hidden in the saved captures; product UI was not altered for the screenshots.

## Verified journeys

- First visit: no product or question is prefilled. The optional-context dialog opened with all eight profile controls empty.
- Text-only investigation: entered a label and asked “How much sodium is in 50 g?” The app parsed the supplied label, displayed a 50 g portion and reported 200 mg sodium. A follow-up asking for 25 g updated the same package and returned 100 mg sodium, with no rescan.
- Mobile and desktop first-visit screens rendered without browser page errors. Axe reported zero violations on the mobile first visit, mobile result/follow-up page, and desktop first visit.
- Product comparison: a controlled 25 g label fixture was compared in-browser with a live Open Food Facts barcode record. Values normalized to 100 g matched the community values; database-only fields remained “not comparable.” The horizontally scrollable comparison is keyboard-focusable. Axe found no violations after that repair. This verifies the transformation and UI, not same-package photo agreement.
- Mobile visual inspection found that “New investigation” and “Add optional context” wrapped in the narrow workspace bar. A mobile CSS adjustment keeps the controls on one line and raises the smallest intake/helper text to 12 px. The fresh mobile capture confirms the wrap is resolved.
- Real browser OCR: one Saffola photo, one Bagrrys photo, and a two-photo Coca-Cola investigation (four genuine public source photos total) were run through the app's current 3,000 px, quality-98 client preparation. No case produced a usable nutrient calculation. Saffola exposed two visually matching nutrient values but no basis, so they remained withheld; Bagrrys returned ambiguous multi-column readings that stayed in conflict; the Coke OCR lacked a reliable value/unit/basis combination. The app left calculated nutrient values unknown. These results are separate from the Node diagnostic and are not a population accuracy estimate.

## Remaining acceptance work

- The photographed labels still fail to yield reliable nutrient calculations automatically. Test an explicitly selected nutrition-panel hint and a tightly targeted crop on real labels; do not weaken ambiguity handling to improve yield.
- A real photo from the same package as each product identity, direct camera hardware, replace/remove interactions, keyboard focus order, color contrast, and the consented Gemini image-selection flow still need dedicated acceptance.
- The Codex in-app screenshot/control route remains unavailable. The Playwright browser runs do not establish phone performance, camera permission behavior, or a fresh interactive audit of every research/results panel.

4. **Conversational follow-up** — [mobile screenshot](evidence/14-synthetic-followup-mobile-390.png). Asking “How much sodium is in 25 g?” updated the same sample package and returned 212.5 mg, without rescanning. Axe found zero violations; no page errors.
5. **Population-scope guard** — [mobile screenshot](evidence/16-under18-sodium-context-mobile-390.png). After explicitly entering “16 years,” asking about blood pressure retained the sample-label calculation (255 mg in the current 30 g amount) but displayed “Adult sodium reference not applied” and requested age-specific guidance. 6. **Catalog comparison and identity wording** — [desktop screenshot](evidence/17-sparse-catalog-comparison-desktop-1440.png), [mobile screenshot](evidence/18-sparse-catalog-comparison-mobile-390.png). The initial screenshot review exposed wording that called a record an “identity match” when only the search-field barcode matched. That copy was corrected before the final comparison screenshots; unit tests cover exact query match with absent package barcode, differing package barcode, and matching recorded barcode.

These checks establish the named rendered flows only. They do not establish full keyboard-order accessibility, phone camera permissions, real-device performance, photo replacement/removal, genuine-photo OCR success, live Gemini behavior, or exact real-package formulation agreement.

## Fresh generalized intake and follow-up review — 21 October 2026

The Codex in-app browser remained disabled in Work settings. I used local Google Chrome through Playwright 1.64 against the existing loopback app at 390 × 844 and 1440 × 1000 CSS pixels. Every accepted screenshot below was captured in this run and inspected. The installed application was not rebuilt or deployed. Axe reported zero violations on the mobile first visit, optional-context dialog, and text-only result/follow-up screen; no page errors or horizontal page overflow were observed.

1. **First visit, mobile and desktop** — [mobile screenshot](evidence/19-first-visit-mobile-390.png), [desktop screenshot](evidence/24-first-visit-desktop-1440.png). 2. **Mobile guidance and optional context** — [guidance card](evidence/20-mobile-guidance-390.png), [context dialog](evidence/21-optional-context-mobile-390.png). The helper instructions now stack vertically on a phone; all nine profile controls were blank, and the dialog remained accessible under axe. The user can skip it.
3. **Open-ended text-only analysis** — [answer screenshot](evidence/22-text-only-answer-mobile-390.png). For the controlled test label, the question “How much sodium is in 50 g?” returned 200 mg with the label basis shown and no personal target implied.
4. **Conversational portion follow-up** — [follow-up screenshot](evidence/23-follow-up-mobile-390.png). Asking about 25 g returned 100 mg in the same investigation without rescanning. Axe reported zero violations and the mobile page stayed 390 px wide.
5. **Flexible photo editing** — in a separate mobile browser session, two public product photos were attached, one optional role hint and one note were set, one image was removed, and the remaining image was replaced. The one-image state and role hint were retained; axe reported zero violations. The photos are from the public benchmark set and were not copied into these screenshots.
6. **Real photo added after analysis** — a genuine public Coca-Cola label photo was read into a text-started investigation. Two existing questions and the selected 25 ml calculation remained available. OCR still contained noisy text (`hy E000` at 41% confidence) outside a recognized ingredient section; it was previously surfaced as a possible additive. The parser now only extracts additive codes from the parsed ingredient section. A unit regression test and repeated Chrome run confirm that the code no longer appears as a finding, while the raw OCR remains available for inspection. This proves incremental workflow and false-positive suppression, not package identity or OCR accuracy.

The current visual audit supports the existing green-toned design direction. Remaining checks include full keyboard-order traversal, camera hardware permissions, replacement under slow/failed file reads, real-device layout and performance, and live Gemini behavior. The Codex `@Browser` surface is unavailable in this environment, so the requested in-app browser itself could not be used; Chrome was the available local-browser fallback.

## Crop intake and real-photo OCR — 21 October 2026

With user approval, a fresh local Chrome/Playwright check exercised the existing loopback app at 390 × 844 and 1440 × 900. The user-selected crop control was dragged on the displayed Saffola label, and the numeric x field was changed by keyboard; the crop overlay tracked both actions. Both screenshots were saved and inspected: [mobile crop intake](evidence/private/01-crop-selection-mobile.png) and [desktop crop intake](evidence/private/02-crop-selection-desktop.png).

1. **Mobile crop intake — good.** Flexible photo intake, optional role hint, and crop controls are present. The crop remains optional; no front/back slots or personal details are required. Axe reported no violations. The long form requires scrolling on a phone; this check did not test whether a physical camera is available.
2. **Desktop crop selection — good.** The same uploaded photo and controls fit the desktop layout. Pointer-drag coordinates matched the requested rectangle, and keyboard editing updated the overlay. Axe reported no violations.
3. **Saffola crop result — partial.** The [mobile result](evidence/private/03-saffola-crop-ocr-mobile.png) contains one correctly read annotated field from the selected crop. The result repeated in a second run; eight of nine annotated values were omitted. The full-image run withheld one value and matched none.
4. **Bagrry's crop result — incomplete OCR.** The [mobile result](evidence/private/04-bagrrys-crop-ocr-mobile.png) rendered without a page error, but its full-image and both crop runs produced no parsed nutrient rows across eight annotated fields. The app did not invent a value.

Across the seven baseline OCR cases, there were zero incorrect annotated fields, zero page errors, and zero axe violations. A follow-up ran the same full-frame and selected-crop paths with the optional contrast control enabled. It yielded zero correct fields and two incorrect Saffola crop fields; the visible sodium calculation was 22,838 mg/100 g despite the label's much smaller printed amount. Contrast returned no correct fields on either photo. This warrants retaining contrast as opt-in and reading each result against the package; the selected sample is too small to quantify general performance. All 11 runs had zero page errors and axe violations. Screenshots for this local run are ignored by Git and remain on this machine; the tracked aggregate receipt is [the browser OCR probe](evidence/real-ocr-browser-ui-probe.json). The check does not establish full keyboard accessibility, camera behavior, real-device performance, label truth, product identity, Gemini behavior, or complete accessibility compliance.

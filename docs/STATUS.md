## Recent generalization correction

The former profile contained one example-specific meal calculator. That schema, extraction helper, production arithmetic, and associated prompt-like UI have been removed. Context now has empty, separate optional fields for dietary preferences, food allergies, food intolerances, health considerations, goals, age group, sex/reference group and location. Allergy and intolerance context stay separate in the UI and prompt assembly; neither is a diagnosis. No default user, diagnosis, goal, country or eating pattern is installed; if every field is blank, the optional Gemini request omits the profile object entirely.

A production-source audit found no prefilled health condition, demographic, diet, product or question. The only sample label is an explicit user-clicked demo marked synthetic throughout the result flow; diabetes references elsewhere are evidence routing and safety boundaries, not a seeded profile or question.

The scanner now supports up to 10 additive image attachments, per-image removal/replacement, optional role hints and notes, a selectable OCR crop target, product descriptions and an initial natural-language question. Existing per-photo OCR still runs locally. Users can start with details alone, paste text, or add images; an image marked as the front or back is optional.

Optional product details now enter the structured package record as a separately sourced user observation, not as OCR label text. The local audit marks them as unverified context, and the Gemini prompt preserves that distinction. Pasted label text can enrich an existing investigation or be analyzed while photos remain attached for a subsequent OCR read. Saved-scan and export disclosures now include user-provided product details. A fresh mobile/desktop Chrome test also added a second real photo after asking an initial question and a follow-up; both turns, the user-changed 50 g amount and add-evidence notice remained. No page errors occurred. The two photographs are separate product listings and do not establish same-variant evidence reconciliation.

Adding photos after the first analysis now enriches the active investigation. Each extracted observation carries its source image ID, and unchanged photos are skipped on incremental reads. Re-reading all photos remains available. Merging retains portion and conversation; identical evidence is deduplicated, different readings on compatible bases remain visible as conflicts, and changed barcode, brand or license evidence triggers an explicit product-identity warning, clears the selected catalog identifier and leaves the search blank. Package-dependent external results are cleared after evidence changes. Automated tests cover preservation, provenance, deduplication, disagreement, incompatible mass/volume bases and identity mismatch. Fresh mobile/desktop Chrome checks verified conversation and amount retention plus the added-evidence notice, but did not establish same-variant matching or OCR field accuracy.

The optional crop now has a direct drag-to-select control over the original photo, with labeled numeric coordinates retained for keyboard use and precision adjustments. A hash-verified Saffola label selection produced the expected rectangle and whole-percent values on mobile and desktop Chrome with zero axe violations and no browser errors. This verifies the interaction and coordinate state, not OCR accuracy for this exact crop.

The calculation control no longer falls back to the sample fixture's 30 g when a real package has no declared serving. It prefers the package's declared serving, then a non-conflicted nutrient basis, and otherwise uses a clearly labeled 100 g/ml comparison reference. This is an amount for transparent arithmetic, not a personal serving recommendation. Regression tests cover each branch; the new visual wording still needs a fresh screenshot review.

Fresh Chrome evidence confirms that an open-ended text-only question can be answered from user-entered label text and followed by a different portion question without resetting the investigation. The mobile guidance card now stacks into one readable column below 700 px, and its heading retains word spacing at narrow widths. The same browser review found and repaired an OCR false-positive additive code: the noisy `hy E000` token appeared outside a recognized ingredient section and is no longer promoted to an additive finding. Original OCR text remains inspectable and noisy, and no accuracy claim is made.

User-declared allergies and intolerances are separate in the profile contract, UI and local reasoning context.

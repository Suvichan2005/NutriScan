# NutriScan research benchmark protocol — 29 October 2026, version 1

This is a preparation freeze, not permission to execute a model benchmark. The production baseline is the completed orchestration audit at `6a9638d`. Application behavior, the report and legacy measurements are unchanged. Machine-readable authority: `data/evaluation/benchmark-protocol-v1.json`; original semester definitions remain unchanged and hash-bound. No model has been selected or frozen by this protocol.

## Dataset and selection

The existing public-catalog convenience sample has now yielded 38 candidate product groups and 102 original source image files, covering noodles, snacks, biscuits, cereals, dairy, beverages, flour/staples and pulses. These are actual acquired bytes, not URLs counted as photographs. Twenty-three previously acquired originals were reused after SHA-256 verification; 79 were downloaded from the official hosts with normal TLS. Source snapshots, uploader attribution, original image IDs, revisions, acquisition dates, byte counts and hashes remain private. No OCR, visual model, or engineering visual inspection of prospective held-out label pixels occurred. Header/dimension decoding verifies file integrity, not food facts or readability.

The collection is **not a representative Indian-market sample**. Country tags, product names, languages and categories are catalog metadata. Camera-photo versus render, exact India formulation, packaging revision, complete panel coverage, printed languages, curved/blurred scans, number of columns, serving bases, allergens, additives and claims remain human-review fields. Existing source image choices changed since the earlier 103-image metadata intake; current original IDs and metadata snapshots, rather than the old count, define this collection. No useful old asset was removed.

Conservative connected brand/family split blocks prevent declared related products crossing splits; known development brands remain development. Where earlier proposals conflict within a block, development takes precedence, then calibration. Current proposal: 20 development, 7 calibration, 11 prospective held-out groups, across 28 split blocks. These are not locked or demonstrated unseen groups. Family/exposure review may merge blocks and reduce the eligible count. No split decision uses model outputs. All crops/captures of a product stay together. Exact image hashes are checked across groups; near-duplicate/relabelled families still require human review.

Image rights follow [Open Food Facts' official licensing guidance](https://openfoodfacts.github.io/documentation/docs/Product-Opener/api/tutorials/license-be-on-the-legal-side/): database, individual contents and images have distinct licenses; embedded packaging artwork may require separate consideration. Attribution is retained. This private local collection is not permission to redistribute images, publish an archive or submit them to a model. Each group remains pending image-specific rights review.

## Independent references and annotations

Use the existing `/research/ocr-annotation` interface, nutrition-pass schema, supplementary text-pass schema, pass comparator and adjudicator. Reader A and Reader B independently view original pixels, without OCR/model outputs, catalog nutrient values or one another's passes. Actual reader codes and dates remain unassigned, not invented. A distinct adjudicator resolves disagreements with image evidence after both passes are immutable. Preserve raw passes, decisions, coordinates and hashes. Readiness metadata cannot authenticate a human or establish scientific truth.

Record nutrient identity and literal label, printed numeric text, numerical qualifier, unit, basis, column and region. Distinguish as-sold/as-prepared, per-100 g/ml, per-serving, package/count and reference-intake columns. Never recover an unreadable digit using arithmetic. For text, retain ingredient sequence/percentages/codes, identity, claims, warnings, serving definitions, contains versus may-contain declarations and explicit readable/ambiguous/not-visible status. Missing does not mean absent or zero. English is primary; original Hindi text can be transcribed where present. There is no language-engine installation milestone.

For table analysis, add explicit row/column spans, literal cell content, empty cells and real cell boxes. These are sidecars to the existing passes, not inferred structure from a flat nutrient list. Grade 1 requires actual independent adjudication; Grade 2 is coordinate-linked owner/developer visual verification; Grade 3 is a model/database candidate and supports only disclosed agreement. Unverified or illegible fields are unscorable. Zero Grade 1/2 references currently exist for this collection.

## Published-method adaptation

| Primary method | What NutriScan adopts | Boundary |
|---|---|---|
| [Nagayi et al., food-packaging OCR study (2025)](https://arxiv.org/abs/2510.03570) | Separate whole collection from human-referenced subset; report coverage, text errors and runtime alongside structured recovery. | Its South African packaging/OCR rankings do not establish Indian package accuracy or column associations. |
| [Smock, Pesala and Abraham, GriTS (2023 revision)](https://arxiv.org/abs/2203.12555) | Table content, topology and location evaluated separately with the pinned official implementation. | A nutrient list is not an annotated grid. Location stays unavailable without actual cell boxes. |
| [Saad-Falcon et al., ARES (NAACL 2024)](https://aclanthology.org/2024.naacl-long.20/) | Separate context relevance, answer faithfulness and answer relevance. | No ARES/PPI confidence claim without the independent calibration labels it requires. |
| [Es et al., RAGAS (EACL 2024)](https://aclanthology.org/2024.eacl-demo.16/) | Evaluate retrieval focus and evidence use separately from fluent answer quality. | Reference-free model judgments are proxies. No judge calls or human-equivalent scores were generated. |
| [Berkeley, BFCL multi-turn methodology](https://gorilla.cs.berkeley.edu/blogs/13_bfcl_v3_multi_turn.html) | Judge valid final state, missing arguments, irrelevant tools and multi-turn state changes; allow alternative correct tool plans. | Not a BFCL score; calls/counts alone do not show useful execution. |
| [Min et al., FActScore (EMNLP 2023)](https://arxiv.org/abs/2305.14251) | Response-bound atomic claim support, plus answer coverage and abstention reporting. | Nutrition applicability needs its own judgment; supplied AI-assisted verdicts remain segregated from human labels. |
| [Dhaliwal et al., NutriBench (ICLR 2025)](https://proceedings.iclr.cc/paper_files/paper/2025/hash/ef3a57e4f26b640e6f90d78cbb011feb-Abstract-Conference.html) | Numerical nutrition evaluation should have explicit references and actual value errors. | Meal-description macro labels are not ground truth for an exact photographed package or personal medical advice. |
| [Zhang et al., NGQA (ACL 2025)](https://aclanthology.org/2025.acl-long.296/) | Evaluate context-sensitive nutrition QA and relationships, beyond text matching. | Population/food-composition graph knowledge cannot substitute for an unreadable package declaration. |

## Reconstruction and scoring

A/B/C/D/E remain exactly the established Tesseract text, Paddle text, original images, Tesseract+images and Paddle+images methods. The same product image set, model/version, generation configuration, reconstruction prompt/output schema, validation and references must be used. OCR-only requests exclude pixels, hidden descriptions and later image recovery. Image-only excludes OCR and saved corrections. Retain raw and normalized outputs privately, including malformed responses, validation failures, retries and unavailable arms.

`scripts/evaluation/score-reconstruction.mts` remains the nutrient scorer. Its complete association precision/recall is primary; inspect value, qualifier, unit, basis, column, omissions and unsupported readings separately. `benchmark_metrics.py` adds one-to-one literal category/text/code matching and ingredient sequence comparison. Semantic paraphrases are not automatically factual errors. CER/WER helpers describe text edits only; they cannot establish a correct nutrition association. Unreadable reference items remain outside clear-field accuracy denominators and are reported separately.

Official GriTS code is MIT-licensed, unmodified and pinned to upstream commit `16d124f616109746b7785f03085100f1f6247575`, with source/license hashes. The adapter requires explicit, complete, non-overlapping bounded cell grids; it does not manufacture geometry. Its synthetic identity, wrong-association and missing-grid tests exercise wiring only. Evaluation-only PyMuPDF dependencies are isolated outside Git, AGPL/commercial licensed, and absent from the application runtime.

Aggregate fields within each product before product-level means. Report the identical completed/scorable product intersection for paired comparisons, and all attempted products/failures separately. Do not count 102 images as 102 independent products. Keep reference grades, initial/recovery stages, model versions and baseline/post-correction phases separate. Any later resampling must cluster related product groups together and accompany raw paired differences; tiny subsets do not justify model superiority. No uncertainty intervals are generated during preparation.

## Conversation, retrieval and grounding

The original nine conversations and 27 exact questions are preserved with original question hashes. Three retained actual application snapshots are schema-valid but exposed/model-assisted Grade 3 contexts, not confirmed label truth. Production calculator execution on these contexts produced offline oracle receipts without network access; arithmetic validity does not verify the label. Nine first-turn knowledge-on/off pairs share package/profile/question hashes, empty initial external evidence/history and the same base prompt. Both treatments use controlled tool access: all ordinary text tools versus calculator/clarification only. No hidden source summaries may enter the off condition.

The separate 12-case/24-turn transfer/adversarial supplement covers multiple portions, topic shifts, corrections, inequalities, marketing pressure, allergen absence/cross-contact, volume/mass, ambiguous bases, source scope/unavailability, label prompt injection and reopening state. Operator events are declared and must be executed/receipted; no event or output is claimed yet. Deliberately altered label text is synthetic and cannot enter the real-photo accuracy denominator. These cases do not change the original nine-case portfolio or introduce ideal answer strings into production.

Reuse the existing 0–4 nine-dimension human review, blinding and adjudication contracts. A score is an actual assessor judgment; null means pending/N/A with reason, never an AI-filled human opinion. The new atomic aggregator validates response quotes and evidence identity, but cannot decide entailment. Separate package facts, deterministic calculations, scientific guidance and interpretation. No cited record automatically proves applicability, safety or current law.

The 24 existing retrieval questions are preserved as development queries. Developer-suggested source IDs are discovery aids, not independent qrels, and must be hidden from assessors. Use the existing runner's 0–3 graded relevance, separate population/jurisdiction/dose/date applicability, complete judged pools, negative cases and unjudged accounting. Recall/MRR/nDCG stay null when judgment gates fail. The curated 29-source snapshot is not a complete rich-source store. Capture the exact active stores/model cache and failure behavior at later execution freeze; unavailable databases must remain unavailable in the result.
